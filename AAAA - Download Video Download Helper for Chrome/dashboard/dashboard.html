Automation

Run the whole pipeline hands-free: capture, clip, convert, deliver.

Highlights from chat

Watches each stream's live chat and saves the moment whenever chat bursts well above its own normal pace — reactions, emotes, shouting and “clip it” requests count most. Each highlight is its own short clip in a Highlights folder, with its score in the name. Chat is read on the stream's page; only per-second counts are used, never the text. Idea credited to OpenShorts, which uses what viewers clipped to find stream highlights.

Chat reacts a few seconds after the moment itself, so a highlight opens well before the burst. Tested against simulated chat at four speeds: medium caught every injected highlight with under one false alarm in five hours of ordinary chat.

Shorts engine

Hands clips to an AI clipping engine you run yourself, which reframes them to 9:16 with face tracking, adds word-synced captions and hook titles, and picks the best cuts inside them. Both are open source and run on your own machine with Docker: OpenShorts (MIT) or SupoClip (AGPL-3.0). StreamClip talks to them over their HTTP APIs; neither is bundled.

Open engine ↗

Clips are always saved by StreamClip first; the engine is an extra. OpenShorts needs a Gemini key (here or in its own .env) or a local LLM; SupoClip needs an API key from its Agents & API page plus its own transcription key.

Auto-clip

Saves every monitored stream as back-to-back segments with no clicks. Segments tile exactly — no gaps, no overlap — and when a stream ends or you stop monitoring, the unsaved remainder is saved too. Manual clip buttons keep working alongside it.

Google Drive delivery

Uploads every clip to a folder in your own Google Drive, in the background, in resumable chunks. StreamClip can only see files it created there (the drive.file permission) — nothing else in your Drive.

No-setup alternative: install Google Drive for desktop and add your Downloads/StreamClips folder to it. Every clip then syncs to Drive with nothing to configure here — leave this switch off.

One-time setup (free, about 3 minutes)
  1. Open Google Cloud Console and create a project (any name).
  2. In APIs & Services → Library, enable the Google Drive API.
  3. In Google Auth Platform, complete the consent screen as External and add your own Google address under Test users.

If an upload fails and the clip was not kept on this computer, it is saved to Downloads instead — a clip is never dropped.

Sending clips to an AI clipping tool

Tools such as Taja take a long video and cut the shorts for you. Taja's site states it imports from YouTube or a file on your computer, in mp4, mov, m4v, avi, mpeg, webm or mkv, up to 5–10 GB and 2–5 hours depending on plan. StreamClip's MP4 output fits that directly:

  1. Keep Output → Format on MP4 and the local copy on. Auto-clips then land in Downloads/StreamClips/…, one folder per site.
  2. Upload those files in the tool's dashboard. Segments of 15–30 minutes stay well inside the size limits.
  3. Google Drive is your archive and gives you the same files from any device.

Capture

How streams are recorded. Changes apply to running captures where possible.

Capture mode

Source buffers the broadcaster's own video segments — the exact bytes the CDN sends, never re-encoded — and always grabs the best rendition offered, whatever quality you are watching at. Tab records what the tab renders: it works on every site but re-encodes.

Source mode downloads the stream a second time alongside the player, so it roughly doubles bandwidth for that stream. If a stream stutters, pick a lower rendition on its card or use tab mode.
